# 设计决策记录（Design Decisions）

记录 L-partner 的关键技术选型与讨论结论。✅ = 已确定，🔶 = 待定。

---

## D1. AI 能力如何接入 ✅

**决策（2026-xx-xx）**：**用户自填大模型 API**。应用不内置 Key，用户在设置页填入自己的 API 地址与密钥，数据只存本地。

推论：

- 必须做一层 **`LLMProvider` 适配层**，至少覆盖「OpenAI 兼容协议」，以便用户接入 DeepSeek / Moonshot / 通义 / OpenAI / 本地 Ollama 等。
- 需要验证浏览器直连的 **CORS** 可行性（国内厂商通常允许，OpenAI 官方默认不允许）。
- Key 存 `localStorage`，需在 UI 中明确提示安全性边界。

**补充建议（待确认）**：**无 Key 时主循环仍需可用** —— 课程、计划、待办、提醒全部可离线使用，只有 AI 相关入口降级为配置引导 + 示例数据。

## D2. 提醒（学习弹窗）的实现形态 🔶

| 方案                              | 能力                               | 限制                          |
| --------------------------------- | ---------------------------------- | ----------------------------- |
| A. 页面内弹窗 + Notification API  | 页面打开时可靠；授权后可发系统通知 | 页面关闭即失效                |
| B. Service Worker + 定时检查      | 页面在后台时仍可能触发             | 调度不保证准时，Safari 限制多 |
| C. 桌面端封装（Tauri / Electron） | 真正的系统级定时提醒               | 交付形态变重                  |

**倾向**：A。技术要点：不用 `setInterval` 轮询，而是计算下次触发的延迟用 `setTimeout`，并在 `visibilitychange` 时重新校准。浏览器限制需在文档中主动说明。

**结论**：待定

## D3. 课程导入 ✅（范围已明确，格式细节待定）

**决策**：支持两条导入路径，最终汇聚到同一个「学习方案」数据模型。

- **路径 A｜自然语言生成教学方案**：用户说出「我想学什么」，由 AI 生成教学方案（目标、阶段、知识点、学时、里程碑），用户可编辑后落成计划与待办。
- **路径 B｜资料 / 电子书导入**：导入电子书或资料文件，解析目录与章节，由 AI 分析生成学习路径，章节转化为任务。

**待定**：路径 B 支持的文件格式范围（epub / pdf / txt / md）。

## D6. MVP 范围 ✅

**决策**：采纳 **P1 闭环优先**。

```
P1  课程/方案创建 → 生成学习计划 → 今日待办 → 到点提醒 → 本地持久化
P2  对话式 AI 助手（角色系统 + 记忆系统）→ 计划自适应调整 → 学习统计
P3  电子书多格式导入 → 导出 / 分享 → 主题
```

> 注：D8、D9 确认后，角色系统与记忆系统可能前移到 P1 —— 它们是本项目的核心亮点，而非可选装饰。

## D8. 角色系统（Persona）✅ 新增

**需求**：除对话框外，提供独立的**角色设置入口**，用户可自行修改角色设定。

设计要点：

- **内置角色模板**：如严格督学、耐心学长、苏格拉底式提问者、简洁助教。
- **可编辑字段**：名字、头像/emoji、身份背景、性格、说话风格、教学策略（先讲原理 vs 先给例子）、禁忌。
- **与记忆的关系**：记忆属于「用户」（跨角色共享），角色属于「当前是谁在教」。切换角色不丢记忆。

**结论**：纳入设计，实现细节待定。

## D9. 记忆系统（对话中不断记忆与进步）✅ 新增

**需求**：AI 在持续对话中不断记忆、并体现「进步」。

**待确认**：做到哪一层（见下方三档）。

### 拟定的记忆分层

| 层          | 内容                                | 说明                                   |
| ----------- | ----------------------------------- | -------------------------------------- |
| 1. 会话记忆 | 当前对话消息                        | 滑动窗口 + 超长时摘要压缩              |
| 2. 事实记忆 | 专业、年级、目标、学习偏好          | 结构化条目，跨会话长期保留             |
| 3. 掌握状态 | 每门课/知识点：未学 / 薄弱 / 已掌握 | 「进步」可量化的部分，可可视化         |
| 4. 情景记忆 | 何时问过什么、当时是否弄懂          | 支持「上次你没弄懂 X，要不要再看一遍」 |

### 关键工程约束

- **写入成本**：不能每轮都调用 LLM 抽取记忆。采用触发式（每 N 轮 / 会话结束时批量抽取）+ 用户手动「记住这个」+ 规则式（从待办完成情况直接推导掌握状态，无需 LLM）。
- **读取方式**：新对话开始时按当前课程/上下文检索相关记忆，注入 system prompt。
- **记忆演化**：条目带 `confidence` / `lastUsedAt`，长期不用降权；用户可查看、编辑、删除（**「我的学伴记得什么」面板**，让记忆从黑盒变为可控）。
- **降级**：无 API Key 时，规则式记忆仍可用。
