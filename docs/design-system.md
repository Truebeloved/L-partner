# 设计系统

> 来源：一份由外部整理的设计约束词（Mono Gray Minimal / Logartis 风格）。
> 本文记录**采纳了什么、修正了什么、偏离了什么，以及为什么** ——
> 设计系统最大的风险不是没人遵守，而是没人知道哪条是刻意的例外。

---

## 一、采纳的核心

单色系：黑 / 白 / 中灰三层表面 + 一个只用于警示的强调色。
层级只靠 **背景深浅 + 边框粗细 + 字重**，不靠阴影堆叠。

### 色彩

| 令牌          | 值                | 用途                     |
| ------------- | ----------------- | ------------------------ |
| `surface`     | `#D0D0D0`         | 页面背景                 |
| `raised`      | `#FFFFFF`         | 卡片、浮层、输入框聚焦态 |
| `sunken`      | `#B9B9B9`         | 输入框、凹陷区域         |
| `ink`         | `#000000`         | 主文字、描边、激活态底色 |
| `ink-soft`    | `rgba(0,0,0,.6)`  | 次要文字                 |
| `ink-faint`   | `rgba(0,0,0,.3)`  | 禁用、极弱提示           |
| `ink-inverse` | `#FFFFFF`         | 深底反白                 |
| `line`        | `#000000`         | 主按钮与强调边框         |
| `line-soft`   | `rgba(0,0,0,.12)` | 卡片与分隔线             |
| `alert`       | `#FF0000`         | **仅警示**               |

### 字号与字重

| 档位      | 规格                             | 用途                         |
| --------- | -------------------------------- | ---------------------------- |
| `display` | 42px / 400 / 1.2 / -0.02em       | 开屏等大标题                 |
| `h1`      | 24px / 700 / 1.3                 | 页面标题                     |
| `h2`      | 21px / 700 / 1.2                 | 区块标题                     |
| `h3`      | 18px / 700 / 1.3                 | 卡片标题                     |
| `body`    | 14px / 400 / 1.5                 | 正文                         |
| `caption` | 14px / 700 / 1.4                 | 强调正文                     |
| `small`   | 12px / 400 / 1.4                 | **补充档位，见下方修正说明** |
| `label`   | 12px / 700 / 1.3 / 大写 / 0.05em | 表单标签、徽章               |
| `micro`   | 10px / 400 / 1.2                 | 极小说明                     |

**只允许两档字重：400 与 700。** 中间的 500 / 600 一律禁止 ——
这是最容易让界面显得"糊"的一处：多个相邻字重会让层级含混，
而只有两档时，每一个加粗都明确表示"这里是重点"。

### 间距

8px 栅格：`4 / 8 / 16 / 24 / 48`（对应 Tailwind 的 `1 / 2 / 4 / 6 / 12`）。
桌面左右边距 24px，卡片内边距 16px，区块垂直间距 48px，按钮横向间距 16px。

### 圆角与形状

- 输入框、小标签：`4px`（`rounded-sm`）
- 卡片、模态框：`15px`（`rounded-card`）
- 按钮、徽章：胶囊（`rounded-pill`）
- 头像、状态点：圆形

禁止尖锐直角（0px）的容器。

## 二、修正：设计约束里两处不能照做的地方

### 1. `Micro 6px` → 改为 `10px`

原约束写 6px 用于角标。**6px 在任何屏幕上都无法阅读**，
也不满足无障碍下限（WCAG 没有最小字号规定，但 6px 的正文对比度实际不可辨识）。
这不是审美分歧，是可用性问题，所以直接修正。

### 2. 补充 `small`（12px / 400）档位

原约束的字号阶梯里**缺"12px 常规字重"这一档**：只有 `label`（12px/700/大写/字距）
和 `micro`（10px）。但时间戳、课程名、次要说明这类文字既不该加粗也不该大写 ——
把它们套上 `label` 会读起来很别扭，套 `micro` 又太小。

所以补了 `small` 一档，填上这个空缺。

## 三、偏离：经确认刻意不遵守的四条

### 1. 布局不采用「居中对称、内容垂直堆叠」

原约束偏向落地页的排版。L-partner 是工具型桌面应用，
采用**固定左侧导航栏 + 右侧内容区**。这条按产品形态决定，不按设计约束。

### 2. 保留极轻阴影（原约束要求完全 flat）

原约束要求「无投影，层级只靠背景色区分」。实测下来这在桌面应用里会失效：
浮层（书籍详情小窗、对话框）**失去了"浮在内容之上"的信息**，
只能靠边框区分，看起来像贴在页面上的另一块内容。

所以保留两层极轻阴影：

- `shadow-lift` —— 卡片、书架隔板
- `shadow-pop` —— 小窗、模态框

**阴影不参与表达层级排序**，只负责"这个东西离开了页面平面"这一件事。

### 3. 书籍保留低饱和彩色（原约束要求纯黑白灰）

这是最重要的一条例外。原约束是单色系、禁止彩色，但本项目的主体是**拟真书架**。

一个全灰的书架不成立 —— 书脊靠颜色与厚度在视觉上区分彼此，
全部灰度化之后，一排书会退化成一排深浅不一的竖条，"书架"这个隐喻就没了。

所以：**界面一片黑白灰，色彩只出现在书脊上。**
颜色因为稀缺反而更跳，比全灰更有冲击力。
配色由课程 id 哈希推导（确定性），限缩在 10 种低饱和"书封色系"内，
保证八本并排不会花。

### 4. 强调色红色只用于警示，不用于激活态

`alert` = 纯红 `#FF0000`，**只出现在**：逾期未完成、错误信息、破坏性操作。

导航选中态、当前课程、进行中状态统一用 **黑底白字**（`bg-ink text-ink-inverse`）。
理由：在中文语境里，一个红色的"设置"菜单项极容易被读成"这里有错误"。
把激活态和警示态用同一个颜色，等于放弃了一个本来很有力的语义信号。

## 四、设计约束是门禁，不是文档

写在文档里的规则三个月后没人记得。所以这里做成了**构建期检查**：

```bash
npm run check:design
```

`scripts/check-design-tokens.mjs` 会扫描全部 `.tsx` / `.ts`，
拦下这些写法：

| 规则                    | 拦下什么                                                              |
| ----------------------- | --------------------------------------------------------------------- |
| `font-weight`           | `font-medium` / `font-semibold` 等中间字重                            |
| `old-brand-palette`     | 旧主题色 `brand-*`                                                    |
| `tailwind-gray-palette` | Tailwind 内置的 slate / indigo / emerald / red / white / black 等色阶 |
| `tailwind-shadow-scale` | `shadow-sm` / `shadow-md` / …                                         |
| `tailwind-radius-scale` | `rounded-lg` / `rounded-xl` / …                                       |
| `font-size-scale`       | `text-sm` / `text-lg` / …                                             |
| `arbitrary-font-size`   | `text-[13px]` 这类绕过档位的任意值                                    |

有意为之的例外可以在**同一行**加 `design-token-ignore` 注释放行 ——
但例外会留在代码里被后来的人看见，而不是消失在习惯里。

## 五、字体：为什么中文必须回退

原约束指定 **Josefin Sans**（标题）与 **Lato**（正文）。
这两个字体**只覆盖拉丁字母与数字，没有任何中文字形**。

也就是说，在一个中文应用里，设计约束的字体身份只对数字和英文生效 ——
中文会全部落到系统默认字体上。与其假装设计覆盖了中文，
不如把这个回退写成显式的一部分：

```css
--font-display: 'Josefin Sans', 'PingFang SC', 'Hiragino Sans GB', 'Microsoft YaHei', sans-serif;
--font-sans: 'Lato', 'PingFang SC', 'Hiragino Sans GB', 'Microsoft YaHei', system-ui, sans-serif;
```

在 Windows 上，中文实际由**微软雅黑**渲染，西文与数字由 Josefin Sans / Lato 渲染。
这个混排是刻意的：数字用 Josefin Sans 的几何字形很精神，
中文用系统黑体保证可读性与字重齐全。

**字体文件本地打包**（`@fontsource/*`），不走 CDN ——
Electron 从 `file://` 加载，离线时外部字体链接会直接丢字体。
