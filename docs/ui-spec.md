### 左侧导航栏

- **固定**，**不随滚轮滚动**（在一级界面恒定存在）
- 包含两类内容：
  1. **索引栏目**：学伴对话、添加书籍等入口
  2. **今日待办**：占住导航栏下方的空白区域常驻显示，**不是独立页面**
- ⏳ 具体条目与视觉**待用户后续补充**

### 书架区

- 拟真书籍，**一排 8 本**（标准窗口宽度下）
- 书籍**大小与高度有协调的错落**——不是随机乱，也不是整齐划一
- 课程不足以填满时，**自动补空白书脊**撑满版面
- 课程多时可滚动

## 5. 窗口自适应 ✅ 已描述

**原则：内容有余量地调整，绝不损失信息。**

- 窗口缩小时整体界面等比缩小
- **空白书脊优先消失**（它们本就是装饰）
- 真实书籍改为减少每行列数重排，**任何真实书籍都不会被隐藏**

**已定的实现口径：**

1. **错落高度必须是确定的，不能用真随机。** 若随机，每次重渲染书高都会跳变，
   鼠标一移、状态一变整排书架就抖。用课程 id 做种子（FNV-1a 哈希）
   生成稳定的伪随机，并用**离散档位**量化高度（连续随机看着乱，离散档位才显得是"设计过的"）。
2. **缩小时的处理顺序**：先削空白书脊 → 再减少列数 → 全程不隐藏真实书籍。

## 6. 视觉风格 ✅ 已定（采纳外部设计约束）

用户提供了一份由其他 AI 从优秀网站提取的设计约束词（单色系 Mono Gray Minimal），
采纳为核心视觉语言。完整记录见 **[`design-system.md`](design-system.md)**。

要点：

- **单色系**：黑 / 白 / 中灰三层表面，层级靠背景深浅 + 边框粗细 + 字重，不靠阴影堆叠
- **只允许两档字重**：400 与 700（禁止 500 / 600 中间字重）
- **字体**：Josefin Sans（标题）+ Lato（正文），中文回退系统黑体（Windows 上是微软雅黑）——
  这两个字体没有中文字形，回退是显式设计的一部分；字体文件本地打包
- **圆角**：输入框 4px、卡片 15px、按钮与徽章胶囊
- **8px 栅格**：4 / 8 / 16 / 24 / 48
- **警示红** `#FF0000` 只用于逾期、错误、破坏性操作

**经确认刻意偏离的三处**（详见 design-system.md）：

1. 保留**极轻阴影** —— 原约束要求完全 flat，但浮层会失去「浮在页面之上」的信息
2. **书籍保留低饱和彩色** —— 全灰书架不成立，书脊靠颜色区分彼此；色彩只出现在书脊上
3. **激活态用黑底白字，不用红** —— 红色的「设置」菜单项会被读成「这里有错误」

**被修正的两处设计约束**：

1. `Micro 6px` → 改为 10px（6px 无法阅读，属可用性问题而非审美分歧）
2. 补充 `small`（12px / 400）档位 —— 原字号阶梯缺少「12px 常规字重」

**约束已做成构建期门禁**：`npm run check:design`

## 7. 动效清单 ✅ 已实现

| 动作 | 动效 | 时长 / 缓动 |
| --- | --- | --- |
| 开屏两屏 | 上浮 + 去模糊 | 见 SplashScreen（唯一"不讲效率"的地方） |
| 书籍悬浮 | 抽出并停住 | 见 Shelf |
| 换页（右界面内容） | 交叉淡入 + 轻微上浮 | 260ms / glide |
| 进出二级界面 | 同上；左栏随页面一起淡出（二级界面是全屏的） | 260ms / glide |
| 一级 → 二级的输入条 | 左右撑开 + 略微变高（生长） | 460ms / 尺寸 spring、位置 glide |
| 进出对话页的输入条 | **不做位移动画**，直接归位 | — |
| 发送后 | 提问先以输入框的样子占满整条 → 压缩到右侧成气泡；回答从左侧长出 | 460ms / spring |
| 回答展开 / 收起 | 高度伸缩（内部可滚，滚动条隐藏） | 420ms / spring |

**缓动只有两档**（见 `styles/index.css` 的 `--ease-spring` / `--ease-glide`）：
"长出来"的动作带一点回弹（Q 弹），"移动"的动作只顺不弹 —— 位移带弹会晕。

**不参与动画的**：左侧导航栏与学伴输入条各自带 `view-transition-name`，
换页时它们**稳在原地**，只有中间的内容淡出淡入。

## 8. 学伴输入条 ✅ 已实现

全应用唯一的 AI 入口，**常驻**在界面上。它不是一个独立的对话区域，
而是一条长条输入框；发问之后当场变成一对气泡（回答浅、提问深），
**整条没有卡片底** —— 页面上看到的就是两个气泡，不是"一块白框里装着两个气泡"。

```
一级界面（内容区顶部，占满内容区横向长度）
┌──────────────┬────────────────────────────────────────────┐
│              │ ┌──────────────────────────────────────┐   │
│  左侧导航栏   │ │ 问问学伴…                         ↑  │   │
│              │ └──────────────────────────────────────┘   │
│              │   页面内容整体下移这条的高度                 │
└──────────────┴────────────────────────────────────────────┘

发问之后：回答在左、提问在右（都占满整条宽度）；回答长就向下生长，盖住页面内容
┌──────────────┬────────────────────────────────────────────┐
│              │ ┌────────────────────────────┬───────────┐ │
│              │ │ 回答（可展开，向下覆盖页面）│ 提问（缩略）│＋│
└──────────────┴─┴────────────────────────────┴───────────┴─┘

对话页：整页就是对话区，输入条平滑位移到底部当输入框
┌──────────────┬────────────────────────────────────────────┐
│              │  消息列表（这一页的正文就是对话）            │
│  左侧导航栏   │ ────────────────────────────────────────── │
│              │ ┌──────────────────────────────────────┐   │
│              │ │ 问问学伴…                         ↑  │   │
└──────────────┴─└──────────────────────────────────────┘───┘
```

| 操作                 | 行为                                                             |
| -------------------- | ---------------------------------------------------------------- |
| 回车 / 点发送        | 提问先以输入框的样子占满整条，再压缩到右侧成缩略气泡；回答从左侧长出来并流式输出 |
| 回答很长             | 气泡向下生长**覆盖**页面内容，不挤压下方（内部滚动，滚动条隐藏，最多 40vh） |
| 回答结束             | 停留 3.2 秒后自动收成长条，两侧都收成省略号                      |
| 点击回答             | 再次展开完整内容；再点收起                                       |
| 点击提问             | 提问**横向生长**，回答被挤成缩略                                 |
| 滚轮（悬停在条上）   | 上下切换历史问答；回答自身可滚时优先滚回答，滚到边界才翻历史     |
| 点 ＋                | 回到输入态，问下一个问题                                         |

**没配置大模型时**：动效照常走（提问照样成气泡、回答侧照样长出来），
只是回答里写的是"还没接入大模型 + 去哪配置"。之前是直接弹一条错误、什么都不动，
从用户视角看就是"发出去没反应"。

**进出对话页**：输入条**直接**落到页面底部（不做位移动画），
换页本身的淡入淡出已经足够交代"换页了"；输入条在顶部和底部之间来回飞只会显得在"变来变去"。

**尺寸与对齐**：输入条占满所在界面的横向长度 —— 一级界面扣掉侧栏、二级界面是全宽，
所以二级更宽一档（高度 48 / 40）。两处的**重心高度**都在 36px、右边缘都在窗口右边距 24px，
从书架点进课程时它只是左右撑开、略微变高，不会上下跳。

**生长与位移**：输入条全应用**只有一份实例**，挂在路由之外；页面上只留一个空位，
输入条量出空位的矩形再贴上去（见 `features/assistant/dock.ts`）。
所以换页时它是 CSS 过渡出来的位移与生长，而不是卸载再挂载；气泡、草稿、
滚动到的历史位置都跟着一起过去。进二级界面会"生长"，进对话页会"滑到底部"。

**会话归属**：与「学伴对话」页**共用同一场对话**（同一个 store）。因此在输入条里问过的问题，
切到对话页能接着聊；同一段上下文也不会被付两次钱。

## 9. 动态回复策略 + 省流模式 ✅ 已实现（默认开启）

### 9.1 动态回复策略（像真人，而不是客服）

**硬性要求：所有角色都要有活人感 —— 不管它是内置的还是用户自己建的。**
只在 prompt 里写一句「回答要简短」是不够的：模型对静态规则的理解是"整体调低音量"，
结果要么仍然长篇大论，要么反过来把每个问题都答成五个字。

所以长度是**每轮现算**的：先判断他这句话是什么性质（`lib/llm/reply-policy.ts`），
再把对应的策略追加到本轮的易变上下文里（不放进稳定前缀，否则缓存会失效）：

| 分类      | 触发                                     | 这一轮怎么回                                       |
| --------- | ---------------------------------------- | -------------------------------------------------- |
| `chat`    | 寒暄、应声、倒情绪                       | 短回一句，别顺势开讲、别借机问学习进度             |
| `quick`   | 很短、又不是要深挖的小问题               | 一两句直接答完，不铺垫、不举例、不延伸             |
| `explain` | 需要解释的问题（默认档）                 | 先给结论，再给最具体的那一点，四五句以内           |
| `deep`    | 明确要求展开，或「为什么？/继续」这类追问 | 可以写长，但像人讲题：一层层说，不加总结、不客套   |

每档还配一个输出 token 上限（200 / 500 / 1200 / 用户设置值）作为安全网 ——
省的是"把寒暄答成一篇"的钱，而不是把回答压短。

稳定准则里同时列了真人质感的硬约束：可以有语气词和一句话回复、可以承认「这个我也踩过坑」、
不要「首先/其次/最后」、不要每段小标题、不要结尾问「还有什么想了解的」。

内置角色的 `speakingStyle` 也都补上了「一次说多少」（督学一句一停、学长一段只讲一个点、
提问者一次只问一个问题、助教能一行就不写两行）；改了这些文案之后，老数据里的内置角色
会在下次启动时按 seed 刷新（见 `store/personas.ts` 的 mergePersonas）。

### 9.2 省流模式

开关在「设置 → 省流模式」。关掉不是"更好"，而是"更贵"：同一轮对话会多带上整棵课程大纲、
更长的历史尾巴和更多记忆条目。压掉的是冗余上下文，不是回答本身。

| 手段                     | 做法                                                                       |
| ------------------------ | -------------------------------------------------------------------------- |
| 前缀稳定以命中厂商缓存   | system 拆成「人设+准则」（逐字节不变）与「课程进度/今日安排/记忆/本轮长度策略」两段，前者在前 |
| 课程段只给当前阶段       | 不再每轮列出全部单元名，只给当前阶段与下一个未完成的单元                    |
| 历史按字符预算裁剪       | 不是"最近 12 条"，而是 4000 字符预算；单条超长截断（保留头尾），**最新的那条回答放宽到 2400 字** |
| 记忆瘦身                 | 注入条数 8 → 5，单条限长                                                     |
| 抽取只发增量             | 记忆抽取只发送自上次抽取以来的消息，已有记忆列表封顶 40 条                   |
| 用量可见                 | 对话页显示「本轮约 N tokens」，不让用户等到月底看账单才知道花了多少          |

## 9. 全局 AI（无前端界面）✅ 已实现

用户看不见它，只看得到结果：待办栏里自己多了东西、课程结构里自己划掉了一行。
**全部挤在已有的那一次「记忆抽取」调用里完成**（每 8 条消息一次），不新增请求、几乎不增加 token。
实现见 `features/today/autoTodo.ts`（规则层）与 `features/memory/extract.ts`（链路）。

| 能力 | 实现 |
| --- | --- |
| 对话里的事自动进待办 | 抽取时同时产出 `todos: [{title, when}]`；`when` 用 `resolveWhen` 解析成人话时间（今天/明天/周三/下周三/3月5日/这周），认不出来兜底成今天 |
| 「这周想做到」→ 周目标 | 抽成 `weekly`，落库时 `date` 与 `weekStart` 都落在本周一 —— 于是它**不会**混进今日清单，而是在左侧待办区置顶成「本周」块 |
| 未来的待办 | 侧栏只显示当天；「今日」页给一个**「接下来」**分区可提前预览与修改。到那天它自己出现在今日清单里 |
| 待办 ↔ 课程关联 | 规则先匹配（单元标题 + 知识点作为别名，命中要求 ≥2 字，避免"学"匹配到一切）；勾掉待办后课程结构里对应单元变灰 + 删除线 |
| 规则拿不准的 | 把待办标题与课程单元清单一起塞进**下一次抽取**让模型给 `todoLinks`；本地再校验一遍标题真能落到某个单元上，避免悬空关联 |

完成判定（`doneUnitIds`）同时认两条链路：计划排期项全部完成，或直接关联的待办全部勾掉 ——
只认一条就会出现"我明明勾完了，课程结构里还是没划掉"。周目标不参与，它颗粒度不对。

## 已确认的技术基础

- **Electron 44** + electron-builder 26（NSIS 安装包）
  - 开发：`npm run dev:desktop`（Vite 起服务 → 拉起 Electron，带 HMR）
  - 打包：`npm run package`（产物在 `release/`，已 gitignore）
  - 快速试跑：`npm run package:dir`
- **零返工的部分**：为静态托管做的 `base: './'` 与 `HashRouter`，
  恰好也是 Electron 从 `file://` 加载所需，现有代码直接能被桌面壳加载。
- **本机信息读取**：渲染进程沙箱化，取不到 Node 的 `os`。
  由主进程经 IPC 提供，预加载只暴露具体能力，不交出 `ipcRenderer`。
- **浏览器调试仍可用**：`npm run dev`（改样式更快，但拿不到计算机名，开屏降级为「同学」）。
- ⚠️ **已知环境坑**：`ELECTRON_RUN_AS_NODE` 若被继承，`electron.exe` 会退化成纯 Node，
  表现为 `require('electron').app` 为 undefined。启动器已显式清除该变量。
